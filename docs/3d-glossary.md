# 프론트엔드 개발자를 위한 3D 용어

웹 UI가 DOM과 CSS를 브라우저에 그리듯, 3D에서는 씬 안의 객체를 카메라 관점에서 캔버스에 매 프레임 그립니다. React는 도구 모음과 데이터 상태를, Babylon.js는 실제 3D 렌더링과 조작을 담당합니다.

| 용어 | 의미와 이 프로젝트에서의 사용 |
|---|---|
| Babylon.js | WebGL/WebGPU 기반 3D 엔진. 직접 그래픽 API를 다루는 대신 모델, 카메라, 빛 등을 객체로 관리합니다. 이 버전은 WebGL Engine을 사용합니다. |
| 엔진(Engine) | 브라우저의 그래픽 장치와 캔버스를 연결하고 프레임을 그리는 기반입니다. |
| 씬(Scene) | 카메라·빛·모델이 들어 있는 3D 작업 공간입니다. DOM 트리 전체와 비슷하지만 화면 밖 객체도 존재합니다. |
| 메시(Mesh) | 삼각형으로 구성된 입체 표면입니다. 로봇 하나가 몸체·바퀴 등 여러 메시로 구성될 수 있습니다. |
| 버텍스 / 인덱스 | 삼각형 꼭짓점의 위치와, 어떤 꼭짓점들을 연결할지 나타내는 데이터입니다. |
| 머티리얼(Material) | 표면의 색, 거칠기, 금속성 같은 성질입니다. CSS 스타일과 비슷하지만 조명의 영향을 받습니다. |
| 텍스처(Texture) | 표면에 입히는 이미지 데이터입니다. 색뿐 아니라 미세한 굴곡 같은 정보를 표현할 수도 있습니다. 기본 로봇은 단색 머티리얼을 씁니다. |
| GLB / glTF | 3D 모델 교환 형식입니다. GLB는 모델 구조와 바이너리 데이터를 한 파일로 묶는 형식이며 압축 파일이라는 뜻은 아닙니다. |
| 모델 / 메시의 차이 | 모델은 저장된 에셋 전체를 말하고, 메시는 그 에셋을 구성하는 렌더링 객체입니다. |
| 좌표계 / 축 | X·Y·Z로 위치를 표현하는 약속입니다. 여기서는 X가 좌우, Y가 높이, Z가 앞뒤입니다. CSS의 Y는 화면 아래로 증가하지만 여기서는 위로 증가합니다. |
| 왼손 / 오른손 좌표계 | 축의 양의 방향과 회전 방향에 대한 약속입니다. Babylon 기본과 glTF의 약속이 달라 로더가 변환합니다. 다른 도구의 값을 옮길 때 확인해야 합니다. |
| 월드 / 로컬 좌표 | 월드는 씬 전체 기준, 로컬은 부모 객체 기준입니다. 부모를 움직이면 자식의 로컬 좌표가 같아도 월드 위치는 바뀝니다. |
| XZ 평면 | 높이 Y를 고정한 바닥 면입니다. 2D 평면의 두 축으로 X와 Z를 사용하는 셈입니다. |
| Transform / TransformNode | 위치·회전·크기를 묶는 변환과, 그 변환을 담는 보이지 않는 부모 노드입니다. 로봇의 여러 메시를 한 덩어리로 조작할 때 씁니다. |
| 피벗 / 원점 | 회전과 크기 조절의 기준점입니다. 기본 모델의 원점은 바닥 중앙에 두어 Y=0으로 배치합니다. |
| 회전 / yaw | yaw는 수직 Y축을 중심으로 방향을 바꾸는 회전입니다. 자동차가 바닥에서 방향을 트는 것과 같습니다. |
| 도 / 라디안 | 각도의 단위입니다. 180° = π rad. 패널과 JSON은 도를 쓰고 엔진에는 `도 × π / 180`을 전달합니다. |
| 오일러 각 / 쿼터니언 | 회전을 표현하는 두 방법입니다. 오일러 각은 축별 각도, 쿼터니언은 회전 합성과 보간에 유용한 4개 성분 표현입니다. 기즈모 결과를 읽을 때 둘 다 고려합니다. |
| 카메라 / ArcRotateCamera | 3D를 바라보는 시점입니다. ArcRotateCamera는 목표점 주위를 도는 관찰 카메라이며 거리로 줌을 조절합니다. |
| Picking / 선택 | 화면의 클릭 위치에서 가상의 광선을 쏴 맞은 메시를 찾습니다. 자식 메시에서 로봇 부모까지 찾아 ID로 선택합니다. |
| 기즈모(Gizmo) | 선택한 객체 위에 뜨는 조작 손잡이입니다. 화살표는 축 이동, 사각 핸들은 평면 이동, 원은 회전입니다. |
| 스냅(Snap) | 연속적인 조작값을 일정 간격에 맞추는 기능입니다. 여기서는 이동 0.5 m, 회전 15°입니다. CSS Grid의 배치 단위와 유사한 역할입니다. |
| 직렬화 / 복원 | 런타임 데이터를 JSON 같은 저장 형식으로 변환하고 다시 구성하는 과정입니다. DOM을 저장하지 않듯 메시 대신 ID·모델 키·위치·회전만 저장합니다. |
| 렌더 루프 / 프레임 | 화면을 반복해서 그리는 흐름과 한 번 그린 화면입니다. React 재렌더와 별개로 Babylon 렌더 루프가 실행됩니다. |
| FPS / 프레임 시간 | 초당 화면 수와 한 화면을 만드는 데 걸리는 시간입니다. 60 FPS는 약 16.7 ms/frame이며 순간적인 긴 프레임은 끊김을 만듭니다. |
| 드로 콜(Draw call) | CPU가 GPU에 내리는 그리기 명령입니다. 메시와 재질 구성이 복잡하면 명령 수가 늘 수 있습니다. |
| 인스턴싱(Instancing) | 동일한 기하 데이터를 공유해 여러 객체를 효율적으로 그리는 방법입니다. 각각 다른 위치·회전을 가질 수 있습니다. 항상 빨라지는 것은 아니므로 같은 조건에서 측정합니다. |
| 웨이포인트(Waypoint) | 이동 경로의 중간 지점입니다. 여러 좌표를 순서대로 연결해 경로를 만듭니다. 장애물 회피나 자동 경로 탐색과는 별도 기능입니다. |
| 보간 / delta time | 두 지점 사이 값을 계산하는 것과 이전 프레임부터 흐른 시간입니다. 일정 속도 이동에는 프레임 수 대신 흐른 시간을 곱해야 합니다. |
| Dispose | GPU 버퍼, 이벤트, 씬 같은 자원을 해제하는 작업입니다. React 컴포넌트 unmount 정리처럼 엔진에도 명시적 정리가 필요합니다. |

## 데이터가 화면으로 이어지는 흐름

`JSON → 검증 → React의 Robot[] → ID별 TransformNode → 자식 메시 → 카메라로 렌더링`

기즈모로 조작하면 반대로 `노드 변환 → 스냅 → Robot[] 갱신 → 속성 패널 표시`가 됩니다. 저장 버튼은 이 배열을 JSON으로 내보냅니다. 카메라와 조명, 기즈모 자체는 배치 파일에 저장하지 않습니다.
